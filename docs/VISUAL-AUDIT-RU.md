## 4. Технические места, которые надо проверить до нового демо

1. **Sample vs whole store.** В текущем ответе API поле sample описывает фиксированные 60 минут, а `data.trades` равно 184 371: база расширилась. Нужны раздельные подписи/запросы `SAMPLE`, `VISIBLE WINDOW`, `STORE TOTAL`. Это наблюдаемая неоднозначность метрик, а не доказательство неверного расчёта рёбер.
2. **Нулевое время.** API возвращает `data.first_ts = 0`. Найти происхождение строк с нулевым временем и исключить ложный 1970 год из диапазона replay; добавить тест. Не стирать данные вслепую.
3. **Единицы подсчёта.** На выбранном кадре 35 distinct wallets и 39 sequence rows; 124 wallets относится к концу большего окна, не к этому кадру. В `queries.graph` node `in_wallets/out_wallets` складываются по рёбрам: один адрес может повториться между рёбрами. Проверить UI-ярлыки; либо подписать сумму edge counts, либо вычислять действительно уникальных адресатов узла.
4. **События для анимации.** Текущий graph recent ограничен последними 25 строками. Новый renderer не должен выдавать polling snapshot за полноценный event stream. Нужен стабильный sequence ID, cursor/backfill и общий replay clock, иначе на высокой скорости события потеряются или повторятся.
5. **Подготовка репозитория.** Git уже отслеживает `data/ingest-60m.log`, `data/probe.json`, `data/serve-badkey.log`, `data/serve.log`, `data/serve.pid`. До публикации провести аудит содержимого и истории, убрать runtime из будущих коммитов. Наличие секретов здесь не установлено. Существующее изменение `data/serve.log` при ревью сохранено.
