## 2. Арт-дирекшн: BLACK / RED TERMINAL

**Актуальное решение владельца: терминал строго чёрно-красный.** Это направление заменяет предыдущую кислотную палитру. Та же система распространяется на web-сцену: две поверхности должны выглядеть одним продуктом.

Характер: глубокий чёрный, крупный красный ASCII `STAMPEDE`, жёсткая моноширинная типографика, тонкие тёмно-красные разделители и редкие ярко-красные события. Рабочий текст — белый и серый. Не весь текст красный: красный собирает внимание на бренде, выбранном маршруте и новом событии. Никаких лаймовых, циановых, маджентовых, оранжевых или зелёных акцентов; никаких стеклянных SaaS-карточек, цветных градиентов и случайного дождя кода.

| Токен | Цвет | Назначение |
|---|---|---|
| background | `#050505` | Основное чёрное поле |
| surface | `#0D0A0A` | Почти чёрные панели с едва заметным тёплым оттенком |
| border | `#351419` | Ненавязчивые тёмно-красные разделители, не мелкий текст |
| primary | `#FF3344` | ASCII-бренд, выбранная дуга, одиночный импульс нового события |
| active-surface | `#260D12` | Фон выбранной строки; белый текст и красный маркер слева |
| text | `#F2F2F2` | Имена пары, главное число, полезные строки evidence |
| secondary | `#A3A3A3` | UTC, адреса, служебные подписи и подсказки клавиш |
| muted | `#747474` | Только необязательные фоновые элементы; не важные подписи |

Композиционный ориентир: 85% чёрных/нейтральных поверхностей, 10% белого/серого текста, 5% красных акцентов. Красный логотип может быть большой массой, но всё вокруг него остаётся спокойным. Никакой сплошной красной заливки экрана. В TUI — чистые ANSI/truecolor цвета, без имитации glow пробелами. В web допустимо короткое локальное свечение выбранного события, без красного тумана по всей сцене.

### Роли и состояния без разноцветного светофора

- **SELL / A:** белый контур узла, явная подпись `A · SOLD`. **BUY / B:** красный заполненный узел, подпись `B · BOUGHT`. Направление задают стрелка и текст, не разница двух почти одинаковых оттенков красного.
- **Главное число:** крупное белое `35 WALLETS` на чёрном; красный отвечает за маршрут и маркер события. Число остаётся вычисляемым, не фиксированным.
- **direct / clean / ambiguous:** текстовые бейджи; ambiguous дополнительно получает пунктир/штриховку и отдельный счётчик. Оранжевый для него не добавлять.
- **LIVE / REPLAY / PAUSED / STALE:** буквальные подписи и различающиеся контуры бейджей. LIVE не получает зелёную точку. Обновление показывают реальные часы/события, не декоративное мигание.
- **ERROR / DISCONNECTED:** заметный блок с инверсией — ярко-красный фон `#FF3344`, чёрный жирный текст `#050505`, знак `!` и конкретная причина. Обычные события такого оформления не получают. Ошибка отличается от бренда композицией и текстом, а не вторым оттенком красного.

Проверь контраст: мелкий полезный текст должен читаться без свечения; тёмно-красный предназначен только для границ/подложек. ASCII и красные маркеры не должны заслонять данные. Проверь truecolor и ограниченный ANSI-режим; при упрощении цветов смысл сохраняют подписи, контуры и выбор строки.

Сохрани IBM Plex Mono для рабочего текста; проверь существующий Bricolage Grotesque для больших web-заголовков, прежде чем добавлять шрифты. На записи 1440×900: основная мысль 48–80 px, названия пары 28–40 px, полезные подписи 18–22 px. Размеры подстраиваются под viewport. Текст evidence в рабочем режиме может быть плотнее, но в presentation увеличивается.

## 3. Настоящий TUI, не HTML внутри рамки терминала

### Запуск и поведение

Реализуй отдельную CLI-команду `terminal`. Вариант интерфейса запуска, который нужно создать и проверить:

```sh
cd /Users/argona/dev/stampede
uv run stampede terminal --api-url http://127.0.0.1:8791
```

TUI читает реальный режим API, а не принимает декоративное `--mode live`. Работа — в нативном Terminal/iTerm без браузера. Можно использовать Textual/Rich; выбор и текущие API проверь по официальной документации при реализации. Повторно сборщик внутри TUI не запускай.

### Композиция

- Сверху крупное красное ASCII `STAMPEDE` на чёрном, затем CHAIN / REPLAY or LIVE / UTC / freshness / visible range. На маленьком окне ASCII сжимается до одной строки; бренд не должен съесть половину рабочей площади.
- Главная широкая зона: реальная хронологическая лента `time · wallet · SOLD A → BOUGHT B · grade`. На каждом обновлении нет полной очистки и мерцания терминала.
- Справа: выбранная пара, число **distinct wallets**, количество sequences, окно и evidence. `↑/↓` выбирают строку, `Enter` раскрывает, `Esc` возвращает, `/` ищет, `q` корректно выходит. Подсказки видны снизу. При непрерывных событиях выбранная строка не прыгает.
- Снизу: hot rotations и sparklines observed-sequences-per-time-bucket. Размер bucket подписан. Рейтинг объясняется числом адресов/изменением за интервал, не скрытой оценкой «инсайда».
- Пустые данные, replay pause, reconnecting, stale, provider error — полноценные состояния, без подстановки демонстрационных чисел. После выхода возвращаются курсор и нормальный terminal mode.

Полноэкранный TUI должен выглядеть насыщенно благодаря реальным данным и иерархии, а не бессмысленным логам. Клавиатурный replay control добавляй только вместе с общим session clock из раздела 5.

## 4. Web-сцена: масштаб и направленное движение

Существующий explorer сохраняет фильтры и evidence. Добавь переключаемый **Presentation / Explore**. Presentation отдаёт сцене не менее 75% площади, убирает пустые боковые панели, но оставляет режим/время/легенду. Состояния доступны обычными действиями пользователя, не только таймером видеозаписи.

### Три состояния вместо одного клубка

**OVERVIEW.** Реальная пространственная сеть с видимым foreground/midground/background. Ограниченный набор подписей, агрегация и LOD; если показана лишь часть графа, напиши `SHOWING N OF M EDGES`. Камера показывает масштаб, но не вращается бесконечно. Пространственная близость — layout для навигации, не дополнительный аналитический факт; это указано в легенде.

**FOLLOW.** Выбор события/пары запускает направленный пролёт 1,2–2 секунды: из обзора к монете A, затем вдоль выбранного маршрута к B. Нужны смена перспективы, перекрытие ближними узлами, параллакс и изменение относительного масштаба; один CSS zoom или pan 2D-холста за 3D не считается. Фон уходит, выбранные A/B становятся крупными и разнесёнными; яркая дуга не скрывает подпись.

**EVIDENCE.** Камера успокаивается. Появляется крупная фактическая фраза:

```text
35 WALLETS
SOLD TRUFFLEHOG → BOUGHT LUNAR
within 30 min · observed sequences
REPLAY 10× · 17:28:37 UTC
```

Это пример из текущего проверенного кадра. В рабочей сцене все числа и имена вычисляются для фактического состояния; не хардкодить 35, 124 или timestamp. По действию открываются строки wallet / sell tx / buy tx / UTC / grade. Режим и смысл сохраняются при скролле.

### Движение внутри сцены

Новые подтверждённые sequences могут давать одиночный короткий импульс вдоль ребра. **Импульс означает одно наблюдаемое событие, не доллар и не доказанный перевод средств.** Основной вес ребра — distinct wallets, это другой счётчик. При большом объёме допустим batching: одна вспышка с подписью `+N sequences`, N привязано к принятой порции.

Повторное получение того же snapshot не запускает новые импульсы. При pause новые события и clock останавливаются; начавшийся короткий эффект может завершиться, но не повториться. На seek состояние пересобирается без «нового» потока всей истории. Reduced motion даёт мгновенный переход; ручное управление прерывает автопролёт. Не применять strobe, случайные тряски, бесконечное orbit или fake network traffic.

Для реального объёма потребуется отдельный WebGL scene renderer или доказуемо трёхмерная альтернатива; один старый Canvas с тенями задачу не решает. Выбор библиотеки остаётся исполнителю после проверки совместимости. Сохрани существующий 2D explorer как рабочий резервный режим и для слабых устройств.

## 5. Общие часы, события, данные — до украшений

TUI и web должны видеть одинаковую выбранную replay session. Не создавай два независимых «текущих времени». Простой серверный clock/session API или явно общий session ID предпочтительнее нескольких случайных таймеров в UI. Изменение play/pause/seek/speed отражается на обеих поверхностях. LIVE не симулируется.

Существующий `/api/graph` возвращает агрегаты и последние 25 recent rows. Для событий добавь стабильный ID и cursor-пагинацию/backfill, достаточные для 10× replay. Сам transport может оставаться polling; WebSocket ради названия не требуется. Контракт должен различать snapshot, newly observed sequences и историю после seek.

Проверь и закрой замечания из аудита:

- Отдельные метрики fixed sample / visible window / full store. Не подписывать 184 371 как размер исходной выборки 146 329.
- `first_ts=0`: диагностировать, отразить unknown time и не строить replay от 1970 года.
- Уникальные кошельки не равны числу sequence rows. По узлу сумма distinct-wallet counts разных рёбер не всегда даёт unique wallets; исправить подсчёт или явную подпись.
- Интерполированное время не показывать как exact и не выводить миллисекундную «скорость обнаружения» из ускоренного replay. Детали точности доступны рядом с evidence.
- Основной вес не включает ambiguous; scope — поддержанные PONS v2 curves и соответствующие Uniswap v4 pools, а не вся сеть. Связь не доказывает общего владельца адресов или источник оплаты покупки. Короткая формулировка находится в кадре/легенде, подробности — в evidence, без длинной мелкой полосы на весь низ.

## 6. Демо: запись работающего продукта

После реализации запиши 20–25 секунд реального исполнения. Возможная последовательность: первые 4 с — настоящий TUI с читаемым брендом и новыми строками; 4–9 с — web overview с понятным масштабом; 9–15 с — выбор события и направленный пролёт; 15–21 с — крупная пара/фактический count и evidence; последние секунды — раскрытие tx-ссылки или возврат в обзор.

Это съёмочный план интерфейса, не данные для подделки событий. Переход между TUI и web допустим монтажом, но с подписью того же replay session/time; не выдавать разрыв времени за непрерывный live. Запиши также отдельный 5-секундный фрагмент pair → count → evidence, который читается без контекста. Не начинай его с пустой панели и ожидания данных.

Покажи owner сырые записи обеих поверхностей, готовые mp4, кадры overview/follow/evidence/TUI и команды воспроизведения. Целевой web render — плавный 60 fps на текущем Mac при размере 1440×900; измерь frame times. Если цель не достигнута, оптимизируй LOD/эффекты и сообщи реальные показатели, а не только экспортный fps файла. TUI обновляется по событиям, ему не нужен искусственный 60 fps redraw.
