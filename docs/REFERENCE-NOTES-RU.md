# Заметки по референсам (просмотрено 2026-09-10, до реализации)

Просмотрено: `bodkin-reference.mp4` покадрово 0–6 с (6 кадров, 1 fps) и 9–18 с (9 кадров), плюс полные кадры 2.5 с и 13 с; `copybara-terminal.png`; собственные `cut-5s-new-events.mp4`, `cut-5s-trufflehog-to-lunar.mp4`, `walkthrough-1440x900.mp4` (кадры). Ниже пять наблюдений: что беру и как оно работает именно для STAMPEDE.

1. **BODKIN, 0–6 с: масса бренда и две реальные консоли.** ASCII-имя занимает ~12% высоты и весь левый верх; под ним одна служебная строка режима (`dry run · budget · max open`). Левая консоль - компактные однострочные записи `time · pass · $TICKER · score · причина`, правая - многострочные записи по событию с инверсными тегами (`FIRE 77`, `WATCH 61`, `SKIP 26`). Для STAMPEDE: левая лента - одна строка на observed sequence `HH:MM:SS · wallet · SOLD A → BOUGHT B · grade`; правая панель - раскрытая пара с строками evidence; инверсный блок - только для ошибки (красный фон, чёрный текст), grade - текстовый бейдж. Числа score/FOMO-текст не переносятся: у нас нет оценки, есть счёт адресов.

2. **BODKIN, 9–18 с: жизнь без мерцания.** Движение - только добавление строк снизу с прокруткой, левая колонка и шапка неподвижны, каждая запись справа завершается строкой `read in 509 ms`. Экран никогда не очищается целиком. Для STAMPEDE TUI: `DataTable` с добавлением строк без `clear()`, автоследование за хвостом, пока пользователь не сдвинул курсор; сверху реальные UTC часы session clock и возраст данных вместо декоративного мигания.

3. **COPYBARA: сетка разной массы, а не равные карточки.** Верхняя строка режима (`REPLAY LOOP · TOKENS KEEP ARRIVING`), слева широкая лента (~60%) с тегом типа события в начале строки, справа узкая колонка `selected` с секциями (`COPY FLOW WALLS`, `HOT MARKET RADAR`), внизу слева таблица объектов с мини-графиками, внизу справа `FLOW / SESSION`. Каждая зона имеет заголовок в верхнем регистре и счётчик. Для STAMPEDE: та же иерархия зон - шапка режима, лента 60/40 с панелью выбранной пары, снизу `HOT ROTATIONS` (пары с числом distinct wallets и изменением за интервал) и `ACTIVITY` (sparkline observed sequences по подписанным bucket). Проценты PnL, COPY SCORE, paper positions, маскот - не переносятся.

4. **COPYBARA: цвет как роль.** Лайм и красный там несут смысл строки (тип события, знак PnL), не декор, и текст остаётся читаемым на чёрном. Для STAMPEDE палитра сводится к чёрному, белому/серому тексту и одному красному `#FF3344`: бренд, выбранный маршрут, маркер новой строки. Тёмно-красный `#351419` только для разделителей. Направление A→B задаётся стрелкой и подписями `A · SOLD` / `B · BOUGHT`, а не двумя оттенками.

5. **Текущий STAMPEDE: что не читается.** На кадрах `cut-5s-new-events` вся сцена - серый клубок с одинаковыми узлами, амбер-импульсы тонут в центре, главное число сидит справа шрифтом 15 px; на `cut-5s-trufflehog-to-lunar` смысл появляется только после клика и всё равно вне сцены. На уменьшенном кадре 720×450 не читаются ни A→B, ни count. Для новой версии: presentation-режим с крупной фразой `N WALLETS / SOLD A → BOUGHT B` в самой сцене, три состояния камеры (overview → follow вдоль маршрута → evidence) в WebGL-сцене с глубиной и перекрытиями, LOD подписей и `SHOWING N OF M EDGES`; старый 2D explorer остаётся резервом.

Отдельно: у референсов A/B нет 3D. Трёхмерная сцена - самостоятельное направление STAMPEDE, и её оценка идёт по собственным критериям приёмки (глубина, параллакс, пролёт к конкретному событию), а не по сходству с референсами.
