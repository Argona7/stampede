## Web-интерфейс — сделать рабочим инструментом, а не шаблонным AI-dashboard

**Направление: чёрно-красная рабочая консоль с чёткой иерархией.** Не новый лендинг и не бесконечная витрина эффектов. Палитра из BRAND.md: чёрный `#050505`, панели `#0D0A0A`, красный `#FF3344`, границы `#351419`, текст `#F2F2F2`/`#A3A3A3`.

Перед правками открыть текущие RADAR/FLOW/MAP/evidence и TUI. Для каждого экрана назвать конкретную проблему и изменение; не ограничиться словами «premium», «clean», «remove slop».

### Что именно привести в порядок

1. **Верхняя панель.** Один компактный бренд-блок; далее понятные режимы RADAR/FLOW/MAP; часы и REPLAY/LIVE; главные controls. Вторичные фильтры — в отдельной рабочей строке/раскрытии, а не кучей равноправных кнопок. Видны активная вкладка, keyboard focus и выбранное состояние.
2. **Иерархия и плотность.** Главный объект экрана читается первым. Убрать пустые гигантские панели и повторяющиеся метрики, оставить разумную плотность строк и интервалы. Границы группируют связанные данные, а не обводят каждый фрагмент. Выровнять padding, baseline, размеры кнопок и подписи.
3. **RADAR.** Читаемая таблица: числовые столбцы выровнены, tabular numerals, единицы/окно видны, заголовки понятны. Symbol + короткий address различают одинаковые тикеры. Выбранная строка не теряется при обновлении; сортировка не уводит объект из-под курсора без объяснения. Колонки с unknown не превращаются в нули. Детали по действию, а не простыня микротекста в каждой строке.
4. **FLOW/MAP.** Названия выбранной пары не перекрываются, стрелка показывает направление, count не спорит с остальными цифрами. Осмысленный focus и возврат в обзор. Пространственное движение и автопилот сохранить как presentation-функции, но ручной ввод их прерывает; рабочий экран не должен всё время летать. Evidence держит нужный контекст и читаемые tx-ссылки.
5. **Состояния и действия.** Проверить loading, empty, error, stale, paused, selected, hover, focus. На пустом экране одна конкретная причина/следующее действие, не мотивационный текст. Обновления краткие и локальные; пользователь понимает, что изменилось. Reduced motion и управление клавиатурой не ломаются.

### Что здесь считается AI-slop

Не добавлять стеклянные карточки, декоративные градиенты, случайный glow, одинаковые rounded-контейнеры для всего, огромные иконки без функции, набор разноцветных бейджей, повторяющиеся подписи и бесконечную пульсацию. Не «исправлять» это тотальным удалением стиля: фирменный красный, пиксельный знак, плотная моноширинная типографика и пространственная карта остаются.

Красный — ограниченный акцент на бренде/выборе/событии. Ошибка отличается явным текстом и композицией, а не ещё одним почти таким же оттенком. Контраст и читаемость важнее атмосферного тёмного текста. Внешний вид должен заметно улучшиться и без анимации, на стоп-кадре.

## Настоящий TUI — отдельная полноценная проработка

- **Композиция:** бренд и режим сверху, основная лента/таблица в центре, детали выбранного объекта в соседней области, краткие shortcuts внизу. При 120×36 не обрезать ключевые данные; при 180×50 использовать место для информации, а не пустых рамок. Screenshot-only раскладка не считается готовой.
- **Чтение потока:** новые события не отбирают выбор/позицию прокрутки. Если пользователь ушёл в историю, показать `N new` и явный `Follow latest`, а не насильно прокручивать вниз. Обновлять изменившиеся строки/поля, не перерисовывать весь терминал с мерцанием.
- **Клавиатура:** arrows, Enter, Esc, Tab, поиск и q работают предсказуемо; выбранная строка, focused pane и active view различаются. Проверить конфликт Tab с переключением Feed/Radar и фокусом ввода; подсказки соответствуют реальному поведению.
- **Типографика:** согласованные ширины колонок, выравнивание чисел, разумное сокращение адресов, UTC/интервал и единицы рядом. Длинное имя не ломает соседние столбцы; полное значение доступно в деталях. Нет таблицы из нечитаемых многоточий.
- **Надёжность:** resize, пустые данные, error/reconnect и выход протестированы. q/Ctrl+C возвращают курсор и нормальный режим терминала; live/replay явно различаются. Настоящие цвета/символы проверены в PTY, есть читаемый fallback.

## Основной гайд: пять шагов

### 1. Prepare your computer

Сначала показать требования и короткую проверку, а не большой install-script. Текущий README указывает Python 3.13, uv, Git и Node 22+ для web. После текущей доработки Fable перепроверить pyproject/lockfile/package.json и указывать реально поддерживаемые версии.

Проверки: `git --version`, `uv --version`, `node --version`, `npm --version`. Дать простое объяснение, как открыть Terminal на macOS, и ссылки на официальную установку отсутствующего инструмента. Объяснить, что копировать нужно команду внутри блока, без символа приглашения `$`.

Не заставлять отдельно устанавливать Python, если выбранный проверенный uv-путь действительно ставит нужный runtime сам. Проверить это на чистой среде и явно написать, кто скачивает Python. Не требовать платных AI-подписок.

macOS — главный проверенный путь. Windows/Linux вынести в отдельные вкладки/разделы только при фактической проверке; иначе явно отметить непроверенность. Не писать «works everywhere» на основании локального Mac.

### 2. Download STAMPEDE

Показать команду клонирования отдельно от подготовки зависимостей:

```sh
git clone https://github.com/Argona7/stampede
cd stampede
uv sync
```

Объяснить: команды выполняются последовательно в одном окне; `cd stampede` переводит внутрь скачанной папки; её путь надо запомнить для второго окна. Если папка уже существует, предложить открыть её/выбрать другое имя, а не удалять данные. Не давать `rm -rf` как универсальное исправление.

После шага дать ожидаемый признак успеха без выдуманного фиксированного вывода зависимостей: процесс завершился без ошибки, появилась среда проекта. Первичная установка и повторный запуск — разные сценарии.

### 3. Build the web interface once

Развернуть текущую длинную цепочку в понятные команды:

```sh
cd web
npm ci
npm run build
cd ..
```

Сказать, что это подготовка браузерного интерфейса и она не запускает отдельный публичный сайт. Команды всё ещё в том же окне, последняя возвращает в корень STAMPEDE. Показывать фактический ожидаемый итог из тестового запуска; не обещать фиксированную длительность для любого компьютера.

### 4. Start the demo and open the browser

```sh
uv run stampede demo
```

Следующий абзац должен быть максимально прямым:

**Leave this terminal open. The command keeps running because it is the server. That is expected. Open http://127.0.0.1:8791/ in your browser.**

Текущий bundle — около 17 MB, распакованная база — около 139 MB; зависимости занимают дополнительное место. Проверить размер актуального release asset. Объяснить, что первое скачивание занимает время и по умолчанию требует интернет, несмотря на отсутствие API-ключей. Дать понятный статус скачивания или описать наблюдаемый вывод. Чистый офлайн-запуск возможен лишь с заранее скачанными зависимостями и бандлом.

Если порт занят, не убивать неизвестный процесс. Проверенный текущий флаг:

```sh
uv run stampede demo --port 8793
```

Тогда браузер: `http://127.0.0.1:8793/`; все клиентские URL тоже используют 8793. Номер запасного порта — пример, проверить свободный порт перед своим тестом.

### 5. See your first result

После загрузки не бросать пользователя перед картой. Дать конкретный маршрут по текущему UI с screenshot каждого ключевого состояния:

1. Найти `REPLAY` и нажать кнопку `Play` — демо запускается в paused, это не зависание. Клавишу Space дать как дополнительный способ.
2. Открыть `RADAR` и объяснить одну строку: монета, число разных адресов, ускорение активности; это ранжирование наблюдений.
3. Выбрать монету и открыть `FLOW` — увидеть монеты, которые эти адреса продавали до покупки выбранной.
4. Открыть выбранное ребро/`EVIDENCE` и найти address, sell tx, buy tx, время. Объяснить distinct wallets vs sequence rows на фактическом примере.
5. При желании перейти в `MAP`, включить autopilot и увидеть тот же набор данных пространственно. Вернуться к чтению evidence, а не закончить только пролётом камеры.

Точные кнопки, клики и клавиши проверить после текущих правок Fable. Пример брать из поставляемого release bundle. Если для него нужен seek к определённому времени, дать точную проверенную инструкцию; не обещать появление нужной монеты «через пару секунд» независимо от состояния.

Завершить шаг явным критерием: **You can now follow an observed sell → buy sequence and open its underlying transactions.** Не подменять его обещанием найти прибыльную сделку.

## Остановка, повторный запуск и обновление

- TUI закрывается через `q`; это не обязательно останавливает API.
- Foreground-сервер останавливается `Ctrl+C` в том окне, где запущен `stampede demo`.
- Повторный запуск: перейти в ту же папку, `uv run stampede demo`; повторно клонировать репо и собирать web каждый раз не требуется.
- Обновление: отдельный короткий раздел с проверкой своих локальных изменений до pull. Не стирать пользовательские файлы, `.env` и базы. После обновления зависимостей/кода показать проверенную последовательность sync/build.

## Troubleshooting: симптом → причина → конкретное действие

Нужна небольшая таблица, минимум следующие случаи; текст ошибок брать из реального воспроизведения, не придумывать:

| Симптом | Что объяснить |
|---|---|
| `git`, `uv`, `node`, `npm` not found | Где установить отсутствующий инструмент и почему после установки иногда нужно открыть новое окно |
| Не находится pyproject/package.json | Как проверить текущую папку и вернуться в нужную, не клонируя всё заново |
| localhost не открывается / connection refused | Работает ли первое окно, совпадает ли порт, что написано в серверном выводе |
| Порт занят | Запустить на другом порту и поменять URL клиента; не завершать чужие процессы |
| Demo download failed | Проверить интернет и release asset, описать manual bundle route без API-ключей; не предлагать прислать секреты |
| Карта стоит | Проверить PAUSED, нажать Play; отличить паузу от настоящей ошибки |
| UI отсутствует / не загрузились assets | Проверить `npm ci` и `npm run build` в web; не запускать второй несовместимый сервер наугад |
| MAP недоступен | Проверить WebGL2/сообщение приложения; показать рабочие RADAR/FLOW/2D варианты, если они доступны в текущей версии |
| Нет X mentions / live market context | В recorded demo внешний контекст выключен намеренно; неизвестное значение не означает ноль |
| TUI мелкий/обрезан | Размер окна и scale шрифта; keyboard hints |

Разбить длинную таблицу на Setup / Running, чтобы не перегрузить страницу. Показать безопасный состав bug report: OS, версия/commit, шаг и обезличенная ошибка. Не просить `.env`, приватные ключи и полный дамп окружения.

## LIVE — отдельный продвинутый путь

Ссылка после успешного demo: `Want current chain data? Live setup →`.
Вынести в отдельный раздел/документ и проверить весь путь с пустым store: Alchemy key, источник/chain, возможная первичная индексация, `serve --mode live`, признаки свежести и provider error. Не считать одним подтверждением вывод `--help`; нужен реальный запуск. Не подставлять старые данные при ошибке под зелёный LIVE.

Владелец сейчас меняет функциональность: инструкции по live могут потребовать обновления. Не менять секреты или рабочий сервер владельца ради документирования; тестировать на отдельном порту и отдельном store. Пока live-путь не проверен, не выдавать его за готовую инструкцию.

## Как это должно выглядеть на GitHub

- В README рядом с Quickstart — видимая ссылка на гайд с понятным названием, не только в нижнем списке docs.
- На странице гайда: небольшое оглавление, пять шагов, отдельно помеченные окна `Terminal 1 — server` и `Terminal 2 — optional TUI`, один логический шаг на code block.
- У каждого шага: действие → команда/клик → что должно получиться → что делать при характерной ошибке.
- Чёрно-красный бренд сохранить, но полезные команды — обычный копируемый Markdown. Не изображать команду картинкой, не генерировать скриншоты с выдуманными успешными выводами.
- Скриншоты можно обрезать до нужной зоны; mode/time и контекст шага сохранять. Подписи и alt text на английском. Большой hero не повторять перед каждым шагом.
- Проверить узкий viewport и light/dark GitHub. Никакого неподдерживаемого JS/CSS. Кнопки-якоря и repo-relative пути реально открываются после публикации.

## Приёмка — гайд считается готовым после исполнения

1. Зафиксировать commit и OS. Взять чистую копию соответствующей версии, без `.env`, без ключей в окружении и без старой demo.sqlite. Не работать поверх параллельных правок владельца.
2. Выполнить команды гайда буквально и в указанном порядке, включая новый Terminal/cwd и загрузку бандла с настоящего публичного release URL. Для проверки использовать отдельный свободный порт, не останавливать сервер владельца.
3. Открыть web, запустить replay, раскрыть реальное событие/транзакции; запустить настоящий TUI, проверить общий clock; остановить и повторно запустить приложение. Снять фактические screenshots.
4. Проверить хотя бы wrong-directory, server-not-running, paused, port-in-use сценарии. Добавить только решения, которые реально сработали. Прогнать текущие tests/build; число тестов не хардкодить по старой версии.
5. Открыть Markdown-render и все относительные ссылки. В отчёт записать точные команды, результаты/exit codes, screenshot paths, какие OS проверены и что не проверено. Отдельно отметить локальную готовность и доступность гайда на публичном GitHub.

### Дополнительная приёмка интерфейса и бренда

Показать логотип в web и TUI, а не только в favicon/README. Снять before/after одинаковых RADAR/FLOW/MAP/evidence на одном диапазоне данных; сравнить читаемость, а не разное количество событий. Запустить TUI в 120×36 и 180×50, выполнить resize, поиск, выбор, приход новых строк, паузу и корректный выход. Проверить web при 1440×900 и 1280×800, узкий viewport не должен прятать единственное действие запуска. Никаких наложений выбранных labels на controls, потери фокуса при обновлении или скачущей строки под курсором. Прогнать текущие Python/web tests, build и lint; показать исправленные регрессии. Скриншоты для гайда делать только после этого.

Не требовать от владельца вручную проверять каждую мелочь; Fable сам проверяет инструкцию. Если найден реальный блокер установки, исправить минимально с учётом текущей работы, а не скрывать его дополнительной фразой в README.
